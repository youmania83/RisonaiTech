1. LangGraph State Machine & Safety Guardrails
The conversation operates on a stateful graph built with LangGraph. Each turn preserves session context while preventing hallucinated medical advice:
State Schema: Carries patient history, provisional chief complaint, verified insurance tier, and selected doctor slot ID.
Emergency Intercept Node: Deterministic regex + zero-shot classification checks for chest pain, acute dyspnea, or severe trauma. Any positive match triggers an immediate hospital emergency escalation prompt with human desk routing.
Deterministic Slot Locking: Booking checks are atomic in PostgreSQL using row-level locking ( FOR UPDATE SKIP LOCKED ) to eliminate double-bookings during concurrent traffic spikes.
2. Prompt Pipeline & Context Injection
System prompts are version-controlled and enforced with strict output schema guarantees:
// Triage System Prompt Template
SYSTEM: You are the clinical intake assistant for [Clinic_Name].
RULES:
1. Never diagnose conditions or prescribe medications.
2. Ask exactly ONE clarifying question per turn to identify primary specialty needed.
3. Output your reasoning in <clinical_thought> tags and patient response in JSON:
{ "specialty": "Dermatology", "urgency": "ROUTINE", "patient_message": "...", "suggested_slots": [...] }
3. PostgreSQL Database Schema
Normalized relational model supporting high-throughput scheduling with full audit logging:
model Appointment {
id String @id @default(uuid())
clinicId String @db.VarChar(64)
doctorId String @db.VarChar(64)
patientPhone String @db.VarChar(20) // E.164 formatted
scheduledTime DateTime
status Status @default(CONFIRMED) // CONFIRMED, RESCHEDULED, COMPLETED, NO_SHOW
intakeSummary Json? // Structured symptoms & chief complaint extracted by LLM
whatsappThreadId String?
createdAt DateTime @default(now())
updatedAt DateTime @updatedAt
@@index([clinicId, scheduledTime])
@@index([patientPhone])
}
